## Purpose

Sub-test A and sub-test B v1/v2 were lexically saturated: a TF-IDF bag-of-words
classifier scored 93-99% on those sets because HarmBench prompts and hand-written
neutral prompts are lexically distinct enough that surface form alone nearly solves the
task. This made it impossible to separate "the activation method captured semantic
content" from "the activation method captured surface vocabulary."

Sub-test B v3 is constructed so that TF-IDF should NOT be able to achieve high accuracy
from surface form alone — aspirational target: 50-65% overall. All 7 Type 1 mutation
sub-groups and both Type 2 source sub-groups must stay below 80% individually. Results
are documented below.

## Mutation Details and Caveat

### Real ciphers (MIT license, from SORRY-Bench encode_experts.py)

All four real ciphers apply a per-item random caesar pre-shift (seeded on item id, fully
reproducible) before the main cipher operation. This breaks the fixed global-vocabulary
problem: a fixed-shift cipher maps every document's vocabulary to the same relabeled
vocabulary, which a bag-of-words classifier learns exactly as it would learn the original.
Per-item random pre-shifts were verified to bring TF-IDF accuracy into range (see tuning
history below).

- **caesar**: per-item random shift only (the "main" operation is already the shift)
- **morse**: per-item random caesar pre-shift, then standard ITU Morse table encoding
- **atbash**: per-item random caesar pre-shift, then atbash inversion (case-correct;
  SORRY-Bench's original has a bug that corrupts uppercase letters to non-printable
  characters — reimplemented correctly here)
- **ascii**: per-item random caesar pre-shift, then space-separated decimal ordinals

### Hand-rolled stand-ins (NOT SORRY-Bench's methodology)

SORRY-Bench's slang, misspellings, and role_play mutations are generated by an LLM
(GPT-4 class). No LLM API key is available in this environment. The versions below are
simple deterministic rule-based approximations that serve the same structural purpose
(each mutation type is applied identically to both classes, so it cannot introduce
label-correlated vocabulary).

**These are NOT SORRY-Bench output and make no claim of matching SORRY-Bench's
behavior.** They are hand-rolled approximations whose fitness for purpose is verified
empirically by the TF-IDF sanity check below.

- **slang**: fixed phrase-level substitution table (please→plz, you→u, for→4, etc.)
  applied to function words, followed by 3 sequential seeded character-level edits
  per eligible content word. Function-word substitutions are label-neutral (the same
  words appear in both classes). The 3-edit pass addresses residual content-word leakage
  that persisted with fewer edits (see tuning history).

- **misspellings**: 2 sequential seeded character-level edits per word of length ≥ 3.
  Each edit is one of: adjacent QWERTY key substitution, letter doubling, letter
  deletion, or adjacent-letter transposition. Seeded on `{item_seed}:{word_text}` so
  the same word within a document always receives the same corruption (internally
  consistent), while different documents produce different corruptions for the same word
  (cross-document varied). 2 ops verified to bring TF-IDF below 80% (see tuning
  history).

- **role_play**: 1 character-level edit per word (same `_inject_typos` function,
  n_ops=1) applied to the content, then wrapped in a fixed neutral template
  ("Let's do a writing exercise..."). The template is identical for both classes
  and contributes zero label signal; it also dilutes the TF-IDF weight of the embedded
  content words (role_play scored 52.0% — already in range, no further tuning needed).

### Why same-algorithm-across-classes matters

Each mutation is applied to both classes using the exact same code path, same parameters,
and same random seed structure keyed on the item's id. There is no mutation that is
applied only to harmful or only to benign content. The randomness (per-item pre-shift,
seeded typos) has the same *distribution* for both classes — what varies across documents
is the specific realization, not the distribution. This ensures that any classifier
learning to separate classes cannot exploit the mutation mechanism itself as a signal.

## Dedup

Near-duplicate check uses the same SequenceMatcher-based convention as `data/splits.json`
(ratio threshold 0.75). An inverted-word-posting-list prefilter limits SequenceMatcher to
candidate pairs that already share at least one distinctive word (length ≥ 4, posting list
≤ 150), reducing the O(n²) scan to a practical runtime.

Reference corpus for dedup:

| File | N strings checked against |
|---|---|
| `data/vectors/train_test_split.pkl` | 2000 |
| `data/harmbench_filtered_250.csv` | 250 |
| `data/neutral_set_300.csv` | 300 |
| `data/subtest_b_neutral_tone_pairs.csv` | 48 |
| `data/subtest_b_harmful_tone_pairs.csv` | 18 |

Type 1 items exclude their own declared source file from the near-duplicate check (a
mutated harmbench item is expected to share words with the original harmbench item;
checking against other reference files still guards against collision with pre-existing
data).

Cipher mutations (caesar, morse, atbash, ascii) skip fuzzy matching entirely: character-
level SequenceMatcher on encoded text vs. plain-text references is structurally near-
impossible to trigger, so only exact-match checking is applied.

Dedup removed from Type 1: 0 (harmbench), 0 (neutral_set).
Dedup removed from Type 2: 6 (xstest), 1 (or_bench).

## Balancing

- **Type 1**: 250 harmful × 7 mutations, 250 benign × 7 mutations = 1750 each.
  Neutral_set_300 was downsampled to 250 (seed=42) to match harmbench's 250 before
  mutation.
- **Type 2**: XSTest 200 safe downsampled from 250 to match 200 unsafe. OR-Bench
  hard-1k (656 actual rows, not 1000) length-matched downsampled to match 655 toxic rows;
  length-matched rather than random to remove a length confound (random downsample had
  r(length,label)=-0.46, length-only classifier 69.6%).
- Post-dedup rebalancing: each (source, mutation) group is downsampled to the smaller
  side. All groups balanced exactly after dedup removal.

**Total: 5200 items (2600 harmful, 2600 benign).**

### Note on the overall vs. the 65% aspirational target

The aspirational construction target was 50-65% overall. The achieved overall is 69.1%.
All individual mutation sub-groups and both Type 2 source sub-groups are below the 80%
flag threshold.

The gap from 65% is accounted for almost entirely by OR-Bench (78.8%) and the Type 2
"none" mutation group as a whole (75.8%), which cover 1700/5200 = 32.7% of the dataset.
OR-Bench uses naturally-written text — "hard-1k" items explicitly frame sensitive topics
("What is the chemistry of explosives?") while "toxic" items make direct harmful requests.
This produces inherent lexical differences (domain vocabulary, hedging language, framing
phrases) that a TF-IDF classifier with sufficient features can partially exploit. Closing
this gap would require either applying surface-form mutations to Type 2 items (which would
change their "naturally-occurring hard pair" design intent) or restricting OR-Bench
further (which would reduce dataset size without addressing the root cause).

The activation extraction study is designed to test whether LM hidden representations
capture semantic content beyond what TF-IDF captures. At 69.1% overall, TF-IDF still
leaves substantial headroom for activation methods to demonstrate an advantage. The key
design goal — no single mutation or source trivially solvable by bag-of-words — is met
for all sub-groups.

## Length Confound Check

| Metric | Value |
|---|---|
| Overall r(length, label) | +0.153 |
| OR-Bench r(length, label) | -0.185 |
| XSTest r(length, label) | -0.013 |
| OR-Bench length-only CV accuracy | 57.6% (flagged: above 55% threshold) |
| XSTest length-only CV accuracy | 44.4% (not flagged) |

OR-Bench length-only accuracy is flagged at 57.6% — this is expected and documented.
After length-matched downsampling, it is the residual driven by a mild positive
correlation between response length and genuine toxicity in the OR-Bench toxic set (toxic
items tend toward terse direct requests). The remaining confound (2.6pp above the 55%
flag threshold) does not dominate OR-Bench's 78.8% TF-IDF score, which is driven
primarily by lexical content differences.
